This project uses ROS 2 Humble and micro ROS to connect high level rover controls with the hardware that performs payload operations. An Xbox controller sends inputs through ROS 2 topics to an Arduino Giga, which controls the elevator, auger, servos, and soil sensor. This design gives the team a modular way to operate the payload while keeping the operator interface, rover computer, and embedded controller connected through a common communication system.

My work focused on the payload control software and its integration with the Arduino Giga. I worked with the micro ROS firmware and ROS 2 teleoperation package that translate joystick commands into commands for AMIS stepper motor drivers, a RoboClaw motor controller, continuous rotation servos, and an RS485 soil sensor. I also worked with launch scripts, diagnostics, topic definitions, and stable device setup so the payload system can be started and tested more reliably. The software includes limit switch checks, command timeouts, status reporting, and reconnection handling to help protect hardware and make issues easier to diagnose during testing.

This project gave me practical experience with robotics software that must interact with real hardware. I learned how ROS 2 nodes, topics, launch files, and message types support communication across a distributed system. I also learned how micro ROS brings that same communication model to a resource constrained Arduino controller. Debugging the payload system taught me the importance of reliable startup procedures, clear hardware documentation, safety checks, and testing each connection in the full control path. Working with Team RoSE strengthened my skills in C++, Python, embedded programming, Linux, ROS 2, micro ROS, and collaborative robotics development.
