My interest in software engineering comes mainly from embedded systems, automation, and using technology to solve real-world problems. I first became interested in programming through Arduino and robotics projects, where I could write code and immediately see it control physical hardware. I like this kind of work because it connects software with something tangible instead of keeping everything on a screen. Over time, that interest led me to work with Python, C++, TypeScript, ROS 2, Git, GitHub, PyTorch, Arduino, and Linux.

## Learning Through Hardware

Arduino was one of my first introductions to programming that felt exciting. Instead of writing code that only printed something to a terminal, I could make a motor move, read data from a sensor, or change how a robot behaved. Seeing code affect the real world made programming feel less abstract and showed me why software matters outside of the computer.

As I worked on more robotics projects, I started to understand that getting a system to work involves more than writing one piece of code correctly. Software has to communicate with hardware, respond to sensor data, handle unexpected behavior, and work alongside other parts of a larger system. That combination of programming, electronics, and problem-solving is what continues to make embedded systems and robotics interesting to me.

## Connecting micro-ROS and ROS 2

One project that has been especially important to me is my micro-ROS project. It involved connecting embedded hardware with ROS 2 so that different parts of a robotic system could communicate and be controlled through software. I worked on the payload control software and its integration with an Arduino Giga, allowing the rover's computer and embedded controller to share information through ROS 2 topics.

This project helped me become more comfortable with hardware and software integration. It also gave me experience debugging problems involving communication, code, wiring, and overall system behavior. In a project like this, an issue can come from many places: a ROS 2 topic may not be publishing correctly, a device may not be connected, a wire may be loose, or a controller may not be receiving the command it expects. Finding the real cause requires working through the entire path instead of assuming the problem is only in the code.

Debugging is one of the areas where I feel most confident because I enjoy narrowing down a problem and determining whether the cause is coming from the software, the hardware, or the connection between them. It is satisfying to take a system that is not behaving correctly, test it step by step, and eventually understand what is happening. The micro-ROS project taught me that reliable systems need clear startup procedures, safety checks, testing, and documentation in addition to working code.

## Growing Beyond Working Code

In the future, I want to improve my understanding of software architecture, algorithms, documentation, and embedded software development. I can usually get a system working, but I want to become better at designing software that is organized, maintainable, and easier for other people to understand. I also want to improve at planning larger projects before immediately starting to code.

Better documentation is another skill I want to develop. It becomes much more important when working with a team or returning to a project after a long period of time. In robotics especially, documentation can explain not only what the code does, but also how the hardware is connected, how a system should be started, and how another person can troubleshoot it safely.

I am still unsure about the exact career path I want to pursue, but robotics and embedded systems are the areas that interest me most right now. I would like to continue gaining experience through larger engineering projects where software has to interact with real hardware. One of my main goals is to become better at building complete systems instead of only focusing on individual pieces of code. Through future courses and projects, I hope to become a stronger software engineer who can design, debug, and document reliable systems that solve practical problems.
